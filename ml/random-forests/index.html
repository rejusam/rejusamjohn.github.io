Bagging and random forests

One tree is jumpy. Many trees, each grown on its own sample of the data, voting together, are steadier, and the rows each tree never saw give you a test score for free.

About 10 minutes · No maths needed; the maths is there if you want it

Overview

The decision trees lesson ended with a tree that fitted its training data perfectly and did worse on new cases. Here we keep the same data and grow many trees instead of one.

We look at how much a single tree changes with its data, build new training sets by resampling, let the trees vote, make them differ on purpose, and then score the vote without a test set.

The points are made up. See "About the data" at the end.

You'll learn

  • what a bootstrap sample is, and why it leaves out about a third of the rows
  • how bagging and random forests turn many jumpy trees into one steadier vote
  • how the out-of-bag rows give a test-like score without a separate test set

    For a number rather than a class (regression), bagging averages the trees' predictions instead of taking a vote.

    Bagging needs no new kind of model: it runs the same method many times on resampled data and combines the answers.

  4. Random forests: make the trees differ

    A random forest is bagging with one more twist: at each split, a tree may look only at a random subset of the features.

    Here there are only two features, so each split looks at one of them, chosen at random, instead of both. A different tree, or a different split in the same tree, may get the other feature.

    Bagged trees all choose from the same features, so they tend to look alike. A vote cancels mistakes only where the trees disagree. Hiding features at random makes the trees less alike.

  5. Out-of-bag: a free test

    Every tree left out about a third of the rows. Those rows can test it.

    For each training row, take only the trees whose bootstrap sample did not include it, and let them vote. That vote is the row's out-of-bag (OOB) prediction. No tree that saw the row gets a say, so it works like a prediction for a new case.

    The OOB accuracy is the share of rows whose OOB prediction is right. A row that every tree saw has no OOB vote, so it is left out of the score.

A random forest uses both: a bootstrap sample for each tree, and a random subset of features at each split.

Lesson complete

  • A full decision tree has high variance: a small change in the data changes the tree.
  • A bootstrap sample draws n rows with replacement. It leaves out each row with probability (1 − 1/n)ⁿ, close to 1/e ≈ 37%.
  • Bagging grows a tree on each of B bootstrap samples and takes a vote. A random forest also lets each split see only a random subset of the features, so the trees differ more.
  • The out-of-bag vote for a row uses only trees that never saw it, which gives a test-like score from the training data.

Common misconceptions

  • "A bootstrap sample is a random two thirds of the rows." It has n rows, drawn with repeats, and on average only about two thirds of the original rows appear in it.
  • "More trees means more overfitting." Adding trees makes the vote settle down, not chase the training data harder. Each tree can still overfit; B is not the knob for that.
  • "Each forest tree must be better than a bagged tree." Here each one was a little worse. The forest wins, when it does, because its trees disagree more.
