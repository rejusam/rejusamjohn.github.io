Tools

A model only writes text. A tool is an ordinary program that the loop runs when the model writes a call for it. Switch the tools on and off and see what changes.

About 9 minutes · Every message, guess and error is computed in your browser; the formulas are in The maths

Overview

In What is an agent? the agent looked facts up and worked out a cost. This lesson looks at the tools themselves: what a tool call is, who runs it, and what the stand-in writes when a tool is missing.

A tool is an ordinary program with a name and an input. The model writes a call for it as text; the loop reads that text, runs the program and adds the program's output to the messages. This page has three tools: a calculator, lookup and a notepad. A fourth tool, send, comes later, in the lesson on mistakes and limits.

You'll learn

  • that a tool call is text the model writes, and the loop runs the tool
  • to read a call's exact input and its result in a trace
  • what goes wrong, and by how much, when a needed tool is off

  1. A model writes text; the loop runs the tool

    A language model takes text in and writes text out. It cannot run a program. A tool is a program that the loop around the model runs.

    The model on this page is a stand-in. On this page the choices come from fixed rules, listed in full in What is an agent?; a real agent makes them with a language model, which can write a wrong or malformed call.

    The task: What is 3 × 1.25 + 2 × 0.8? The stand-in writes the call calculator("3*1.25+2*0.8"). That call is only text. The loop reads it, finds the tool's name and its input, runs the calculator and adds what the calculator returned, 5.35, as a new message. On its next turn the stand-in is given that result and answers "The sum is 5.35." The run takes 2 steps.

    Select a row of the trace: the picture marks who made it. Plan lines, calls and the answer are text the model wrote; a result is what a tool returned; the stop comes from the loop.

  2. A tool call up close

    A call names one tool and gives it an exact input. Its result is the tool's exact output.

    The three tools on this page, with the one-line description each one carries:

    • calculator: Works out an arithmetic sum such as 3*0.8+2.
    • lookup: Looks up one person or one food in the invented world.
    • notepad: Writes a line to the notes, or reads all the notes back.

    The trace is the eli task from the last lesson: 3 tool calls in 4 steps. Its first call is lookup("eli"): the tool is lookup and the input is key = "eli". The loop runs lookup on that input, and the result row holds its output word for word: "eli likes plums and lives by the lake."

    Select any plan, call or result row: the picture shows that step's call and its result. Nothing in between is changed or summarised.

    The maths

    A tool is a function of its input:

    result=tool(input)\text{result} = \text{tool}(\text{input})result=tool(input)

    Here the same input always gives the same result. The notepad also depends on the notes written so far in the run.

  3. Calculator off

    With the calculator off, the stand-in cannot get an exact sum. Its guess rule fills the gap.

    The guess rule for sums: round each number to one significant figure, then work the sum out exactly. For this task 3 stays 3, 1.25 becomes 1, 2 stays 2 and 0.8 stays 0.8, so the guess is 3*1+2*0.8 = 4.6.

    The run takes 1 step, with no tool call: the stand-in applies R4 and R6 and writes "The sum is 4.6." The calculator gives 5.35, so the guess is wrong by 0.75. Select the plan row: Why this step quotes both rules.

    This is a simplification. A real language model has no rounding rule like this one; it writes the digits of an answer as tokens, and those digits can be wrong. A calculator gives the exact sum each time.

    The maths

    Write r(x)r(x)r(x) for xxx rounded to one significant figure. For a sum of products ai×bia_i \times b_iai​×bi​:

    guess=∑ir(ai) r(bi),error=exact−guess\text{guess} = \sum_i r(a_i)\, r(b_i), \qquad \text{error} = \text{exact} - \text{guess}guess=i∑​r(ai​)r(bi​),error=exact−guess

    Here the exact sum is 5.35 and the guess is 4.6, so the error is 0.75.

  4. Lookup off

    With lookup off, the stand-in has no way to get a fact. It guesses one and goes on.

    The task: eli buys 4 of the food eli likes. With lookup off, the stand-in applies its guess rule: the first food in its food table, apples, at the first price in its price list, $0.80. The calculator is still on, so it calls calculator("4*0.8") and answers that it costs $3.20, in 2 steps. Its first plan row applies R3 and R4.

    In the invented world eli likes plums, at $1.25 each, so the true cost is $5.00. The answer is wrong by $1.80. The sum was exact; the facts it used were not.

  5. Each tool on or off

    Switch each tool on or off. The eli task runs again at once, and the line under the tools says whether its answer is right, or by how much it is wrong.

    The checkboxes sit next to Run and Next message. Only the runs with both lookup and the calculator on are right. With lookup on and the calculator off, the stand-in rounds the sum to 4*1 and answers $4.00.

    The notepad changes no answer here. With lookup on, the stand-in applies R2 after each lookup and writes the fact in the notes: the run with every tool on takes 6 steps instead of 4, 2 more, with the same answer. With lookup off there is no fact to write, so the notepad changes nothing. The notes matter when old messages drop out of what the model is given, which is the lesson on memory.

    The maths

    Three tools, each on or off, give 2 × 2 × 2 = 8 runs. Each one is computed in your browser, and each is the same every time.

Quick check

Why give a model a calculator?

Right. With the calculator off, the stand-in's guess was 4.6; the calculator gave 5.35.

A model can write numbers, as text. The trouble is that those digits can be wrong, and nothing in the text says so.

The model does not change. It writes a call; the loop runs the calculator and passes the exact result back.

Prices come from lookup. The calculator only works out sums, such as calculator("3*1.25+2*0.8").

Who runs the tool: the model or the loop?

Right. The model only writes text, such as lookup("eli"). The loop runs lookup, and the model is given the result on its next turn.

A model only writes text. Writing lookup("eli") runs nothing until the loop reads it.

A tool is an ordinary program; something has to call it. Here the loop does, after reading the call.

No person is involved here: the loop runs every call. The lesson on mistakes and limits shows a case where the loop waits for a person's yes before a tool that changes things.

Lesson complete

  • A model only writes text. A tool call is text naming a tool and its exact input; the loop runs the tool and adds its exact output as a new message.
  • With a needed tool off, the stand-in's guess rule fills the gap, and the answer is wrong by an amount you can work out: 0.75 for the sum, $1.80 for the eli task.
  • Here the tools give exact facts and sums. Real tools can fail; a later lesson shows what the loop does then.

Common misconceptions

  • "The model runs the tool." It writes the call as text; the loop runs the tool.
  • "More tools always help." Here the notepad changes no answer on the eli task and costs 2 extra steps.
  • "A guessed answer looks different." "The sum is 4.6." reads as well as "The sum is 5.35."; only the trace shows which one came from the calculator.

About the data. Nothing here is random: the same task, tools and rules give the same trace every time. The tasks use the invented world from Level 5, where each person likes one food: ana apples, ben pears, eli plums, mia figs, noa limes, sam grapes, tom apples, zoe pears. The invented price list is apples $0.80, pears $1.10, plums $1.25, figs $2.40, limes $0.60, grapes $3.50. The calculator works out a sum exactly and shows it rounded to at most two decimal places. The stand-in's guesses are the first food in its food table, the first price in its price list, and each number of a sum rounded to one significant figure (half away from zero).
