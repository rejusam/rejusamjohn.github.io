ML Explorer · Level 6 · Agents

What is an agent?

A model answers once. An agent runs the model in a loop: choose an action, act, get the result, repeat. Watch both on the same question, one message at a time.

About 9 minutes · Every message, step and sum is computed in your browser; the formulas are in The maths

Overview

In Level 5 a language model wrote text one token at a time. An agent puts a model like that in a loop: the model writes what to do next, an ordinary program does it, and the result goes back to the model as a new message.

In this level, an agent is a program that runs a model in a loop, with tools the model can write calls for, until the model writes an answer or a stopping rule ends the run. The tasks use the invented world from Level 5: made-up people, the food each one likes, and a made-up price list. Its facts are rules of this page, not claims about anyone.

You'll learn

  • that an agent runs a model in a loop: read, choose an action, act, see the result, repeat
  • how to read a trace: the task, plan lines, tool calls, results, the answer and why the run stopped
  • why the agent's answer here is right where a single answer was a guess

  1. One question, one answer

    Ask a model a question and it writes one answer. Here: what food does mia like?

    Look at the rows under the picture. This is the trace: one row per message, here the task and the answer.

    The answer, "mia likes apples.", is wrong: in the invented world, mia likes figs.

    The model here is a stand-in that follows fixed rules. With no tools, its guess rule picks the first food in its list, apples.

    Select the answer row: the "Why this step" box shows the rules used, R3 and R6 (two of six, all shown in step 5). "Run" replays the trace; "Next message" adds a row.

    Note: a real system uses a language model instead, and it can write wrong text.

    The maths

    One answer is one model call:

    answer=model(task)\text{answer} = \text{model}(\text{task})answer=model(task)

    Nothing the model writes is checked or acted on before it becomes the answer.

    A real language model has no guess rule like the stand-in's. It writes text by predicting the next token, from the question and the patterns in its training text, and as a tiny language model showed, fluent is not the same as true.

  2. Add a tool and a loop

    Now add a tool, lookup, which finds a person or food in the invented world.

    Look at the boxes. The loop goes round them: read (the model is given the task and every message so far), choose, act, see result, until an answer goes to stop.

    On its first turn (one model call) it writes a plan line, a short note of its next move, then the call lookup("mia").

    A call is only text. The loop, a plain program, runs the tool and adds its result as a new message.

    On its second turn it is given that result and answers "mia likes figs." This level calls a turn a step: 2 steps here.

    The maths

    Write historyt\text{history}_thistoryt​ for the task and every message before step ttt. Each step applies the same function to it:

    actiont=policy(historyt)\text{action}_t = \text{policy}(\text{history}_t)actiont​=policy(historyt​)

    Here the policy is the stand-in's rules; in a real agent it is a language model. If the action is a tool call, the loop runs the tool, and historyt+1\text{history}_{t+1}historyt+1​ is historyt\text{history}_thistoryt​ followed by the plan line, the call and its result. If the action is an answer, the run stops. A step is one model call.

  3. A longer task takes more steps

    Now a task that needs two facts and a sum: eli buys 4 of the food eli likes. What does that cost?

    Look at the line under the loop: it says which step the selected row belongs to. A plan line, its call and the call's result share one step.

    The agent now has a second tool, a calculator. The first lookup gives the food eli likes, plums. That result is now a message, so the second lookup can ask for its price: $1.25 each. Then comes calculator("4*1.25").

    The run makes 3 tool calls, stops after 4 steps and answers $5.00.

    The maths

    Every step is one model call, so a run of 4 steps makes that many model calls. In this run every step but the last calls one tool, so it makes 4 − 1 = 3 tool calls. With a real language model each call takes time and computing, which is why the next lessons count them.

  4. The guess against the agent

    The eli task again: one answer with no tools, next to the agent's.

    Look at the two boxes: one answer on the left, the agent on the right.

    The stand-in guesses both facts: eli likes apples, at $0.80 each, the first price in its list. Its rules R3, R4 and R6 (guess a fact, guess a sum, answer) give $3.20.

    The true cost, 4 × $1.25 = $5.00, is the agent's answer. The guess is wrong by $1.80.

    Both read equally well; only the agent's rests on looked-up facts and the calculator's sum.

    Note: a real model asked once might be wrong or right, and the answer gives no sign of which.

  5. The six rules behind the stand-in

    Last, the stand-in itself: six fixed rules, R1 to R6.

    Look at the six boxes. Select a row: the rules it used get a thick outline, and the "Why this step" box quotes them.

    On each turn the stand-in tries the rules in order and applies the first that fits. On the first turn the task needs a fact that is not yet in the messages, so R3 applies: call lookup.

    This run uses R3, R4 and R6. R1, R2 and R5 come up in later lessons.

    Note: a real agent has no rules like these; a language model writes the plan line and the call as text.

    The six rules in full

    On each turn the stand-in tries these in order and applies the first that fits. A rule that guesses then goes on to the next rule.

    • R1 If the last result says "not found": answer that it was not found, or call the same lookup again, or guess (the first food in the food table or the first price in the price list) and go on to the next rule, as set.
    • R2 If the notepad is on and the last result is a fact not yet in the notes: write it in the notes.
    • R3 If the task needs a fact that is not in the messages or the notes: call lookup for it. With lookup off, guess the first food in the food table or the first price in the price list, then go on to the next rule.
    • R4 If the task needs a sum and no calculator result for it is in the messages: call the calculator. With the calculator off, or sums set to guess, round each number to one significant figure, work out the sum exactly, then go on.
    • R5 If the task asks to send a message and none has been sent: with send off, answer that it cannot send; with ask before changes on, ask a person first; otherwise call send.
    • R6 Otherwise: answer from the facts, and the sum if there is one.

Quick check

What makes an agent different from a single model answer?

Right. One answer is one model call. An agent calls the model again and again, runs the tool calls the model writes, and adds each result to the messages, until the model writes an answer.

On this page both use the same stand-in rules. The difference is the loop and the tools: with them the eli cost comes out at $5.00, without them at $3.20.

An agent can still be wrong: a tool can fail, and a language model can write a wrong call. Later lessons show such cases.

Each run here starts from the task alone. Within a run the model is given the messages so far; the lesson on memory shows what happens when they no longer fit.

Where did the $5.00 come from?

Right. The stand-in only wrote the call calculator("4*1.25"). The loop ran the calculator, its result went back as a message, and the answer uses it.

The task text has no prices in it. The stand-in wrote a call to the calculator, and the number came back as the calculator's result.

lookup gave the facts: eli likes plums, at $1.25 each. It does not work out the total.

The guess rule is what the one answer used, and it gave $3.20.

Lesson complete

  • One answer is one model call. An agent runs the model in a loop: read everything so far, choose an action, act, see the result, repeat until it answers.
  • A trace shows every message: the task, plan lines, tool calls, results, the answer and why the run stopped. Each step is one model call.
  • Here the tools give exact facts and sums. The model only writes the calls as text; the loop runs them.

Common misconceptions

  • "An agent is a new kind of model." It is an ordinary model run in a loop with tools; on this page the model is a stand-in made of six rules.
  • "An answer that reads well is right." "mia likes apples." reads as well as "mia likes figs.", and only one is true.
  • "The model runs the tools." It only writes the call as text; the loop runs the tool and passes the result back.

Further reading

  1. Russell & Norvig, Artificial Intelligence: A Modern Approach (4th ed.), Chapter 2, "Intelligent Agents": agents in general, well beyond language models.
  2. Yao et al., "ReAct: Synergizing Reasoning and Acting in Language Models", arXiv 2210.03629 (2022), in which a language model writes short free-text steps in between actions such as searches, and is given each action's result before the next.

About the data. Nothing here is random: the same task and the same rules give the same trace every time. The invented world from Level 5 gives each person one food: ana apples, ben pears, eli plums, mia figs, noa limes, sam grapes, tom apples, zoe pears. The food table lists the foods in this order: apples, pears, plums, figs, limes and grapes. The price list, also invented, is apples $0.80, pears $1.10, plums $1.25, figs $2.40, limes $0.60, grapes $3.50. lookup answers from these, and for a person it also gives the place they live, which no task here needs. The calculator works out a sum exactly and shows it rounded to at most two decimal places. The stand-in's guesses are the first food in the food table, the first price in the price list, and each number rounded to one significant figure.
