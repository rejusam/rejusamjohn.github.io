Predicting the next token

A language model does one job: given the text so far, it gives a probability to every possible next token. Build one from counts, type a few letters to see its guesses, and make it write.

About 10 minutes · Every count, probability and bit is computed in your browser; the formulas are in The maths

Overview

A language model reads text as tokens, as in Tokens: text as numbers, and predicts the next one. It does not pick a single answer: it gives every token in the vocabulary a probability. Writing text is then repeated guessing: pick a token from those probabilities, add it to the text, and ask again.

To keep every number checkable, the tokens here are single characters and the model is the simplest one there is: it counts which character came next in a training text. The text describes the small world invented for this level: eight made-up people, the food each one likes and the place each one lives. Its facts are rules of this page, not claims about anyone. The last lesson, Embeddings: words as points, used the same world.

You'll learn

  • that a language model gives a probability to every possible next token, and writes by sampling from them one at a time
  • how temperature reshapes those probabilities, from always taking the likeliest token to near-random
  • how cross-entropy on held-out text measures a model, and why longer contexts help until the counts run out

  1. One bar per character

    A language model gives every possible next token a probability. Here a token is one character.

    Look at the bars: one per symbol, 28 in all (space, full stop and 26 letters). Each is the probability that it comes next after "mia li". ␣ marks a space.

    The model looks only at the last 3 characters, "␣li". That piece is the context, and its length is n. So it never sees "mia".

    "␣li" begins likes, lives and limes in the training text, so k, v and m get almost all of the probability. The 28 bars add up to 1.

    Note: large language models usually use pieces of words as tokens. Characters keep the counts small enough to show.

    The maths

    Write the text as tokens x1,x2,…x_1, x_2, \dotsx1​,x2​,… from the vocabulary V\mathcal{V}V, here the 28 symbols, so ∣V∣=28|\mathcal{V}| = 28∣V∣=28. A model with context length n gives, at each position t,

    p(xt=v∣xt−n,…,xt−1)  for every v∈V,∑v∈Vp(xt=v∣xt−n,…,xt−1)=1.p(x_t = v \mid x_{t-n}, \dots, x_{t-1}) \ \text{ for every } v \in \mathcal{V}, \qquad \sum_{v \in \mathcal{V}} p(x_t = v \mid x_{t-n}, \dots, x_{t-1}) = 1.p(xt​=v∣xt−n​,…,xt−1​)  for every v∈V,v∈V∑​p(xt​=v∣xt−n​,…,xt−1​)=1.

    Looking only at the last n tokens is the Markov assumption behind n-gram models. Here n is the context length; the usual name counts the whole run of n + 1 characters, so this is an (n + 1)-gram model. It is a simplification: the next character can depend on text further back, as the name does here.

    From step 3 on, the "context n" slider changes n. Large language models usually predict subword tokens, from vocabularies of tens of thousands of tokens or more.

  2. Bars from counts

    Where do those bars come from? From counting what came next in the training text.

    Look at the bars: how often each character followed "␣li" in the training text of 2,000 sentences (42,030 characters).

    "␣li" occurs 1,699 times: k follows 830 times, v 782 and m 87. So the probability of k is about 830 out of 1,699: 0.488.

    First each count gets a small extra k = 0.01 (add-k smoothing; here k is a number, not the letter). So a character never seen after "␣li" gets 0.0000059, not 0.

    A context never seen in training has all its counts 0, so every character gets 1/28.

    The maths

    With c(context,v)c(\text{context}, v)c(context,v) the number of times v followed the context in the training text, and c(context)=∑vc(context,v)c(\text{context}) = \sum_{v} c(\text{context}, v)c(context)=∑v​c(context,v),

    p(v∣context)=c(context,v)+kc(context)+k ∣V∣,k=0.01.p(v \mid \text{context}) = \frac{c(\text{context}, v) + k}{c(\text{context}) + k\,|\mathcal{V}|}, \qquad k = 0.01.p(v∣context)=c(context)+k∣V∣c(context,v)+k​,k=0.01.

    For the context "␣li": p(k∣context)=(830+0.01)/(1699+0.01×28)≈0.488p(\mathrm{k} \mid \text{context}) = (830 + 0.01) / (1699 + 0.01 \times 28) \approx 0.488p(k∣context)=(830+0.01)/(1699+0.01×28)≈0.488. Adding k to each of the 28 counts adds k ∣V∣k\,|\mathcal{V}|k∣V∣ to the total, so the probabilities still add up to 1. With all counts 0 the formula gives k/(k ∣V∣)=1/28k / (k\,|\mathcal{V}|) = 1/28k/(k∣V∣)=1/28. With k = 0 these are the maximum-likelihood estimates: the plain shares of the counts.

    Without k, a context followed in other text by a character never seen after it would give that character probability 0, and the measure in step 5 would be infinite.

  3. Type your own text

    Now choose the text. Type in the box under the picture; the bars show what comes next.

    Look at the chips under the box: the outlined ones are the context, the last n known characters. The "context n" slider sets n from 1 to 8.

    Try "zoe likes ", then "zoe li", then letters that never appear in the invented world.

    If the context never occurred in training, or there are fewer than n known characters, every bar is 1/28.

    Note: capitals become lower case. A digit, comma or emoji shows as a dashed chip with a ? and is skipped. What you type is never stored or sent.

    The maths

    The probabilities come from the formula in step 2, with the context taken from your text. With n = 1 the context is a single character, so the model can only learn which letters tend to follow which. Each extra character of context splits the counts into more, smaller groups.

  4. Draw, add, repeat

    To write: draw at random, add, repeat. Temperature τ reshapes the bars first.

    Look under the picture: text written at four temperatures. The "temperature τ" slider picks which the bars show.

    τ = 1 uses the model's own probabilities; smaller τ sharpens them, larger τ flattens them. τ = 0 always takes the likeliest (greedy); ties, like h and l after "he␣", are broken at random.

    "Generate" uses a new seed each press. τ changes only the drawing, not the counts.

    Over many presses (at n = 3, from the starting text), τ = 0 repeats a few words; τ = 1.5 gives more words outside the invented world.

    The maths

    Temperature τ is applied to the log-probabilities with the softmax from Embeddings: words as points:

  5. Score it on new text

    How good are the guesses? Test the model on text it never counted.

    Look at the bars, one per n: scores on held-out text, 300 new sentences never counted.

    The model gave the true next character probability p, costing −log⁡2p-\log_2 p−log2​p bits (0 for a sure, right guess). The average is the cross-entropy; lower is better. A 1/28 guess costs 4.81.

    With the full text, bits fall from 1.99 at n = 1 to 0.47 at n = 3, then only to 0.31 at n = 8.

    Now switch to "Small training text" (the title shows which). Held-out bits are lowest at n = 3, 0.59, and rise to 1.32 at n = 8, while the training dashes stay low (0.33 at n = 8): good on counted text, poor on new text.

    The maths

    The cross-entropy over the N positions of the held-out text that have n characters before them is

    H=−1N∑tlog⁡2p(xt∣xt−n,…,xt−1).H = -\frac{1}{N} \sum_{t} \log_2 p(x_t \mid x_{t-n}, \dots, x_{t-1}).H=−N1​t∑​log2​p(xt​∣xt−n​,…,xt−1​).

    It is the many-class form of the log-loss from logistic regression, averaged over positions, in base 2 so it reads as bits. The uniform guess gives log⁡228≈4.81\log_2 28 \approx 4.81log2​28≈4.81 bits. An unseen context gets the uniform guess, so it costs exactly log⁡228\log_2 28log2​28 bits; with the small text at n = 8, those 15.3% of positions alone add 15.3% × 4.81 = 0.74 bits per character to the average.

    The held-out text is made with a different seed from the training text. With the full training text no held-out context is unseen, at any n. The eight lines under the picture are generated at n = 1 to 8 with τ = 1. Over many presses, from the starting text, at n = 1 most of the complete words are not words of the invented world; from n = 3 on nearly all of them are.

  6. Why counting runs out

    Why the rise? Each extra character gives 28 times as many possible contexts.

    Look at the lines (full text solid, small text dashed) and the "unseen" row.

    That row is the share of held-out contexts the small text never saw: up to 15.3% at n = 8. Each costs the full uniform guess, 4.81 bits, so the dashed line turns up after n = 3.

    The full text copes because the world is tiny. Of the 28828^8288 = 377,801,998,336 possible 8-character contexts it has only 731, yet every held-out context is among them.

    Counts treat every context on its own: with n = 7, seeing "mia lik" many times teaches nothing about "zoe lik", although an e comes next in both.

    The maths

    With ∣V∣|\mathcal{V}|∣V∣ symbols there are ∣V∣n|\mathcal{V}|^n∣V∣n possible contexts of length n, and each needs its own row of ∣V∣|\mathcal{V}|∣V∣ counts. A training text of M characters fills at most M of those rows, so once ∣V∣n|\mathcal{V}|^n∣V∣n is far larger than M almost all rows are empty.

    The world has 26 different words in three sentence patterns, so even long contexts repeat. Real text is far less regular than this world, so with long enough contexts most contexts in new text have never been seen, even in a very large training text. Neural language models address this by sharing what they learn across similar contexts, for example through embeddings like those of the last lesson, so a context they never saw can still get sensible probabilities. The ones that write text are trained on the same job, predicting the next token with cross-entropy as the loss, at far larger scale. The next lessons build the parts of one, starting with attention.

Quick check

What does temperature 0 do?

Right. All the probability goes to the largest one. That is why the τ = 0 samples keep repeating a few words; a tie, such as h and l after "he␣", is split at random.

That is the other end: as τ grows very large the probabilities flatten towards uniform. τ = 0 sharpens them completely.

That is τ = 1. Temperature 0 keeps only the likeliest token.

Temperature changes only how the next token is picked from the probabilities. The counts, and so the model, stay the same.

Why does held-out cross-entropy matter more than training cross-entropy?

Right. With the small text at n = 8 the training text costs 0.33 bits per character but new text costs 1.32: the long contexts memorise the 50 sentences. The same idea as the test error in earlier levels.

It is usually higher, not lower: at n = 8 with the small text, 1.32 held-out against 0.33 on the training text.

Speed is not the reason. Held-out text is used because it was not counted, so it shows how the model does on new text.

They can be close, as with the full text here, but with the small text and long contexts they are far apart.

Lesson complete

  • A language model gives a probability to every possible next token; it writes by sampling one token, adding it, and repeating.
  • Temperature τ reshapes the probabilities: τ = 1 is the model itself, τ = 0 always takes the likeliest token, larger τ flattens towards uniform.
  • Cross-entropy on held-out text measures a model in bits per token. Longer contexts help until more and more of the contexts in new text were never seen in training; each of those costs the full uniform guess.

Common misconceptions

  • "More context is always better." With the small text, held-out bits rise after n = 3, from 0.59 to 1.32, because more and more contexts were never counted.
  • "The model picks the right next character." It gives probabilities; a sampled text is one random draw from them, and a different seed gives a different text.
  • "Temperature changes what the model learned." It only changes how the next token is drawn from the same probabilities.

About the data. The world is invented: eight made-up people (ana, ben, eli, mia, noa, sam, tom, zoe), six foods and four places, with a fixed table of who likes which food and lives where. Its facts are rules of this page, not claims about anyone. All the text is made in your browser by the mulberry32 random number generator: the training text is 2,000 sentences from seed 261, the held-out text 300 sentences from seed 262, and the small training text 50 sentences from seed 264. For each sentence, one uniform draw u and then a person chosen uniformly: if u < 0.4 the sentence is "<person> likes <their food>.", if u < 0.8 it is "<person> lives by/in the <their place>.", and otherwise "<person> and <friend> are friends.", with the friend drawn uniformly until it differs from the person. The sentences are joined with single spaces. The counts use add-k smoothing with k = 0.01. Generated text starts at seed 263, and each press of Generate adds 1 to the seed.
