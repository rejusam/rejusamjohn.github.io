Decision trees

Label a case by asking it a few yes/no questions, each one chosen to sort the classes apart as well as it can.

About 10 minutes · No maths needed; the maths is there if you want it

Overview

Logistic regression and the support vector machine split the plot with one straight line. A decision tree works differently. It asks a question about one feature, splits the cases into two groups, and then asks a new question inside each group.

We start with one question, measure how well it sorts the classes, let the tree choose its own questions, and then grow it too far on purpose.

The points are made up. See "About the data" at the end.

You'll learn

  • how a tree labels a case, and how the Gini impurity scores a split
  • why the tree chooses its questions one at a time, and what that costs
  • why a very deep tree is perfect on the training data and worse on new cases

  2. How mixed is a side?

    To compare questions, measure how mixed each side is. The Gini impurity is 0 for a side of one class and 0.5 for an even mix.

    Write p for the share of triangles on one side. Its Gini impurity is G = 2p(1 − p). A side of all circles (p = 0) or all triangles (p = 1) has G = 0. A half-and-half side has G = 0.5, the most mixed two classes can be.

    To score a whole split, average the two sides' G, weighting each side by its share of the cases. This is the weighted Gini. Lower is better.

    The thresholds a tree tries are the midpoints between neighbouring values of the feature, once sorted. Any threshold between the same two values makes the same split, so nothing is missed.

    Why not score a split by how many cases it gets right? A split can make both sides purer without changing either majority, and a count of errors would not notice. Gini does, and purer sides give the next questions a better start.

  3. The greedy choice

    The tree tries every threshold on every feature and keeps the split with the lowest weighted Gini.

    So the x₂ split wins, and the tree's first question is "is x₂ less than ?".

    This search is greedy: it takes the split that is best right now and never looks ahead to the questions that could follow.

    Then the tree does the same inside each side: each one gets its own best question, and so on down. This is called recursive binary splitting.

  4. Growing the tree

    Repeat the search inside every region and the tree grows. The maximum depth caps how many questions in a row a case can be asked.

    Move the max depth slider from 1 to 8. Each new level can split every region again, so the regions get smaller.

    Every region is a box with sides parallel to the axes. Each question looks at one feature only, so every cut runs straight across or straight up.

    At max depth 2 one leaf holds 1 circle and 1 triangle. That is a tie, and the tie rule sends it to class 0.

    From depth the tree stops growing: all leaves are pure, so there is nothing left to split.

    The diagram draws three levels below the root. Deeper parts appear as dashed boxes with the number of splits hidden below them. The shading always shows the whole tree.

    The maths

    The depth of a leaf is the number of questions on the way to it. A tree of depth ddd has at most 2d2^d2d leaves, and fewer when some branches stop early.

    Max depth is one way to stop a tree. Others set a smallest leaf size, or grow a big tree and then cut back the branches that help least, which is called pruning.

  5. Too deep

    Training accuracy climbs all the way to 100% as the tree deepens. Test accuracy does not follow.

    This is the overfitting lesson again, with depth in place of the curve's degree. In practice you choose the depth on a validation set, not on the test set.

    The maths

    Each label was flipped with probability 0.1, wherever the point lies. So even the rule that made the data is expected to be wrong on 10% of new cases, and no classifier can expect to do better than 90% here.

    A tree grown until no split helps almost always ends with pure leaves, and then its training accuracy is 100% by construction. That comes from how it grows, not from anything it has learned about new cases.

    Searching every possible tree is hopeless beyond tiny examples: the number of trees grows far too fast. So trees are grown greedily, and the result is a good tree rather than the best possible one.

    Lower impurity on the training cases is not the same as higher accuracy on new ones. The point here is only that the greedy tree is not the best tree by its own measure.

Lesson complete

  • A decision tree labels a case by a chain of yes/no questions, each about one feature. Its regions are boxes with sides parallel to the axes.
  • Each split is chosen to give the lowest weighted Gini impurity, G = 1 − Σ pₖ², which is 2p(1 − p) with two classes.
  • The search is greedy: the best split now, with no looking ahead. That keeps it fast, but the tree it finds is not always the best one.
  • Depth is the overfitting knob. A full tree is perfect on the training data and learns its noise; choose the depth on a validation set.

Common misconceptions

  • "The tree finds the best possible set of questions." It finds a good set, one question at a time. A different first question can lead to a better tree.
  • "A deeper tree is a better tree." Past a point it fits the noise in the training data, and new cases suffer.
  • "Trees need their features standardised, like k-NN." Multiplying a feature by a positive number moves its thresholds with it, and every split separates the same cases.
