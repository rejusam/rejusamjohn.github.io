Naive Bayes

Describe each class on its own, then let Bayes' rule say which class a new case most likely came from.

About 12 minutes · No maths needed; the maths is there if you want it

Overview

Logistic regression learns the boundary between the classes directly. Naive Bayes goes the other way round. It learns what each class looks like, feature by feature, and then asks: for a case like this one, which class is more likely?

We start with plain counts, swap them for smooth curves, slide the class shares, move to two features, and finish with data that breaks the method's main assumption.

The points are made up. See "About the data" at the end.

You'll learn

  • how Bayes' rule combines a prior and a likelihood into the probability of each class
  • what the "naive" assumption is and why it gives axis-aligned ovals, and why different spreads curve the boundary
  • why Naive Bayes can label well yet be too sure of its probabilities

  1. Bayes' rule with counts

  2. A smooth curve for each class

    Swap the bars for one smooth curve per class. Then we can read the chance of each class at any value of x₁, not just band by band.

    For each class, Naive Bayes fits a normal curve, the bell shape, to that class's values of x₁, using the class's own mean and standard deviation. The fitted curve, p(x₁ | class), is the likelihood: how typical the value x₁ is of that class.

    Each curve is drawn multiplied by its prior, 0.6 for class 0 (solid) and 0.4 for class 1 (dashed), so it sits over that class's bars. The area under the class 0 curve is 0.6 and under the class 1 curve 0.4. Class 1's curve is narrower and, even after multiplying by its smaller prior, taller, because its cases are less spread out.

    The curve in the lower panel is the posterior, P(class 1 | x₁): the height of the class 1 curve divided by the sum of both heights. Move the x₁ slider to read both heights and the posterior at any point.

    At x₁ = 3.5 the class 0 curve is higher, and P(class 1 | x₁) = . The curves cross at x₁ = , where the posterior is exactly 0.5. That is the decision boundary: to its right, Naive Bayes predicts class 1.

  3. The prior moves the boundary

    Change the prior and the boundary slides, although neither curve changes its shape.

    The slider sets P(class 1) by hand, from 0.1 to 0.9. P(class 0) is 1 minus it. The value counted from the data is 0.4.

    Raise P(class 1) and the class 1 curve grows taller while the class 0 curve shrinks. Their crossing moves left, towards class 0, so more values of x₁ are predicted class 1. Lower it and the boundary moves right.

    Why set a prior by hand? Because the training data may not have the class shares you will meet in use. If one class was deliberately over-sampled for training, the prior should be set to its real share.

    The maths

    Take logs of the ratio of the two posteriors (the log-odds):

    log⁡P(1∣x1)P(0∣x1)=log⁡P(1)P(0)+log⁡p(x1∣1)p(x1∣0)\log\frac{P(1 \mid x_1)}{P(0 \mid x_1)} = \log\frac{P(1)}{P(0)} + \log\frac{p(x_1 \mid 1)}{p(x_1 \mid 0)}logP(0∣x1​)P(1∣x1​)​=logP(0)P(1)​+logp(x1​∣0)p(x1​∣1)​

    The prior only adds a constant. Raising P(1)P(1)P(1) raises the log-odds by the same amount at every x1x_1x1​, so the posterior goes up everywhere and the stretch where it is above 0.5 can only grow. The boundary is where the log-odds is 0.

  4. Two features: the naive step

    With two features, Naive Bayes fits one curve per feature and multiplies them. Treating the features as unrelated within each class is the "naive" part.

    Now both features count. A case is x = (x₁, x₂). For each class, fit a normal curve to feature 1 and another to feature 2, then multiply: p(x | class) = p(x₁ | class) × p(x₂ | class).

    That product is right only if, within each class, knowing x₁ tells you nothing more about x₂. This is called independence, and assuming it is why the method is called naive. In this data it holds: each class was made with no link between its two features.

    The ovals mark where each class's product is constant, 1 and 2 standard deviations from the class mean along each feature: solid for class 0, dashed for class 1. They line up with the axes and can never tilt, because the product has no term that links x₁ and x₂.

  6. When independence fails

    When two features move together within a class, Naive Bayes counts the same evidence twice. Its probabilities tend to become too sure of themselves.

    This is a second data set, made in the same way except that within each class feature 2 rises with feature 1. Correlation measures how closely two features rise and fall together, from −1 to 1. In the training cases it is in class 0 and in class 1. The clouds are tilted, but Naive Bayes's ovals cannot tilt.

    For each test case, call the probability the model gives to the class it picks its confidence. If those probabilities are honest, the average confidence should be close to the share of cases it gets right.

    The reason: when x₂ moves with x₁, a high x₂ mostly repeats what a high x₁ already said. Multiplying the two curves counts that evidence twice, which pushes the probabilities towards 0 and 1.

    The labels hold up better. The rule built from the true tilted shapes, the best possible on average, scores on the same test cases. Naive Bayes is points behind it, less than its confidence is off by. Trust its labels more than its probabilities.

    The maths

    Take the extreme case, a feature copied twice, x2=x1x_2 = x_1x2​=x1​. The product is p(x1∣c)2p(x_1 \mid c)^2p(x1​∣c)2, so the log-odds term for that feature is counted twice and the posterior is pushed further from 0.5 than the evidence justifies. With a correlation of 0.85 the double count is partial, not complete.

    The true-shape rule uses the real means, standard deviations, correlation (0.85) and class shares (0.6 and 0.4) that made the data. On average over new cases no rule makes fewer mistakes, but in practice you never know those values; it is here only as a yardstick.

    Mean confidence is the average over the test cases of max⁡cP(c∣x)\max_c P(c \mid \mathbf{x})maxc​P(c∣x). Comparing it with accuracy is a rough check of calibration: whether the probabilities mean what they say.

Quick check

What does "naive" assume?

Right. That is what lets the method multiply one curve per feature. It is the part that fails on correlated data, where the probabilities came out too sure.

If the features told you nothing about the class, there would be nothing to learn. The assumption is about features among themselves, once the class is known.

No. The prior is counted from the data, 0.6 and 0.4 here, and the boundary moves when it changes.

That is the choice of curve in this lesson's version, Gaussian Naive Bayes. Other versions use other curves, or counts, and are just as naive. The naive part is the independence.

On feature 1 alone, doubling class 1's prior (0.4 to 0.8) moves the boundary which way?

Right. It moves from x₁ = to x₁ = . P(class 0) falls to 0.2 at the same time, so the class 1 curve grows and the class 0 curve shrinks.

The other way. A larger prior makes class 1 more likely everywhere, so more values of x₁ end up on its side.

The boundary is where the posterior is 0.5, and the prior changes the posterior at every point. So the boundary moves.

There is no simple rule like that. A larger prior adds the same amount to the log-odds everywhere, which moves the boundary left, towards class 0. How far depends on how steeply the two curves change near the crossing.

Lesson complete

  • Bayes' rule: the posterior P(class | x) is proportional to the prior P(class) times the likelihood p(x | class).
  • The prior is estimated from the class counts; the likelihood comes from a curve fitted to each class. Changing the prior moves the boundary.
  • The naive assumption treats the features as independent within each class, so the likelihood is a product of one curve per feature.
  • When features move together, Naive Bayes counts the same evidence twice: the labels can stay good while the probabilities become too sure.

Common misconceptions

  • "Naive Bayes only works when the features are independent." Its labels are often good anyway; it is its probabilities that suffer.
  • "The prior is a formality." It shifts every posterior and moves the boundary.
  • "A likelihood is the probability of the class." It is the other way round: p(x | class) is how typical x is of the class. P(class | x) is the posterior.
