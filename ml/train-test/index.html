ML Explorer · Level 2 · Learning from data

Train, validate, test

A model is only useful if it works on data it has not seen. Here is how to measure that honestly.

About 10 minutes · No maths needed; the maths is there if you want it

Overview

So far every lesson has scored a model on the same points it learned from. That score flatters the model. This lesson holds some points back, scores the model on them, and shows how to choose a setting without fooling yourself.

The points are made up. See "About the data" at the end.

You'll learn

  • why the error on the training data is usually too optimistic
  • what a test set is, and why one test score is only an estimate
  • how a validation set or k-fold cross-validation chooses settings, leaving the test set for the end

  1. A score on its own data flatters a model

    A rule can fit the points it learned from perfectly and still be a poor guide to new points. Its score on those points is optimistic.

    Each of the 40 points is a smooth wave, y = sin(πx), plus some random noise. We made them, so we know the true curve: the dotted line.

    The grey line is a rule that joins the dots. Between two neighbouring points it predicts along the straight line that joins them. On these 40 points every prediction is exact, so its mean squared error (MSE, Lesson 4) is 0.

    The true curve scores worse on the same points: MSE . It misses each point by exactly that point's noise.

    Yet for a new point the true curve is the better guess. The new point brings its own fresh noise, and joining the dots has copied the old noise. A score on the points a model learned from cannot show you this.

    For points (xi,yi)(x_i, y_i)(xi​,yi​), i=1,…,ni = 1, \dots, ni=1,…,n, and predictions y^i\hat{y}_iy^​i​,

    MSE=1n∑i=1nei2,ei=yi−y^i\text{MSE} = \frac{1}{n}\sum_{i=1}^{n} e_i^2, \qquad e_i = y_i - \hat{y}_iMSE=n1​i=1∑n​ei2​,ei​=yi​−y^​i​

For the true curve, ei=εie_i = \varepsilon_iei​=εi​, so its MSE is the mean of the squared noise.   2. Hold some points back

    Before fitting, set some points aside. The model learns from the training set. The test set plays the part of new data.

    Here 30% of the 40 points, 12 of them, are picked at random to be the test set: the violet squares. The other 28, the cyan dots, are the training set.

    The model never sees the test points while it learns. Afterwards, its error on them estimates its error on new points from the same source.

    The split is random so that the test points are like new data. Points picked by hand, say all those with large x, would test something else.

    The maths

    For one fitted curve and independent test points, the test MSE is a mean of ∣T∣|T|∣T∣ independent squared errors. Its SD is the SD of one squared error divided by ∣T∣\sqrt{|T|}∣T∣​, so four times as many test points halve the swing.

  5. Choose with validation, test once

    To choose a setting such as the degree, compare the options on validation data taken from the training set. Keep the test set for one score at the very end.

    Suppose you tried degrees 1, 2, 3 and so on, and kept whichever scored best on the test set. The test set would then have helped pick the model, and its score would be optimistic for the same reason as a training score.

    A validation set is a part of the training data held back to compare settings. k-fold cross-validation does this more thoroughly. Split the training points into k parts; here k = 5. Each part takes one turn as the validation set, while the model is fitted on the other four. Then average the k validation scores.

    The bars show that average for degrees 1 to 6. Degree scores lowest. It is refitted on all 28 training points and only then scored on the test set, once: test MSE .

    Try New split in step 4 and come back: the chosen degree can change with the split. That is the same noise again.

    Every training point is in the validation part exactly once. This plain average treats the parts as equal; weighting each by its size is another common choice.

Quick check

Why not choose the degree by trying each one on the test set?

Speed is not the problem. Scoring a fitted curve on 12 points is quick.

Right. Once the test points have been used to choose, they are no longer new data. Use a validation set or cross-validation to choose, and the test set once at the end.

Nothing is fitted on the test set either way. The trouble is using its score to choose.

It may pick a fine model. What breaks is the score: it no longer tells you honestly how the model does on new data.

In 5-fold cross-validation, how often is each training point in the validation part?

Every part takes a turn as the validation set, so every training point is validated on.

Right. The five parts do not overlap and each takes one turn. In the other four rounds the point is used for fitting.

Four is how often each point is used for fitting: in every round except its own part's turn.

There are five rounds, but in four of them the point is used for fitting, not for validation.

Lesson complete

  • A model's error on the points it learned from is usually lower than its error on new points. It is optimistic.
  • A test set, held back at random, gives an honest estimate of the error on new data. With few test points, that estimate is noisy.
  • Choose settings with a validation set or k-fold cross-validation, inside the training data. Score on the test set once, at the end.

Common misconceptions

  • "A low training error means a good model." Joining the dots scores 0 on its own points and copies their noise.
  • "The test MSE is the model's true error." It is an estimate from a handful of points, and another split gives another number.
  • "Cross-validation uses the test set." It works inside the training data. The test set stays untouched until the end.

About the data. The 40 points are made up, from a seeded random number generator, mulberry32 with seed 3. For each point in turn, x is drawn uniformly between −1 and 1, then y = sin(πx) plus 0.25 times a draw from a normal distribution with mean 0 and SD 1. The points miss the wave only because of that noise; real data also has measurement error and things the model leaves out, and usually no known true curve. The first split shuffles the point numbers with a separate mulberry32 generator, also seeded 3; each New split adds 1 to that seed. The 5 cross-validation parts are consecutive runs of the shuffled training points. Displayed values are rounded; the calculations are not.
