ML Explorer · Level 6 · Agents

Build your own agent

An agent is a handful of parts you can name and choose. Choose them, run your agent on three tasks, and take it home as a small Python program.

About 12 minutes · Every run, every pass or fail and the program itself are computed in your browser

Overview

The last five lessons took an agent apart: the loop in What is an agent?, tools in Tools, the step limit and the repeat check in The loop and when to stop, the window in Memory, and asking before changes in Mistakes and limits. Here you put the parts together.

Your agent runs on three fixed tasks, and the page says whether each one passes, and why. Then the same agent appears as a Python program that you can copy, read and run on your own computer, with no model and no network.

You'll learn

  • to name the parts of an agent and choose each one
  • how one choice can make a task pass or fail
  • how your agent looks as a program, and which part a real model replaces

  1. The parts

    An agent is a handful of parts you can name and choose.

    The model in your agent is a stand-in: its choices come from the 6 fixed rules listed below, and your Python program carries the same rules. A real agent makes these choices with a language model, which can write a wrong or malformed call.

    Choose each part with the controls under the picture:

    • Instructions: what to do when lookup finds nothing (say so, try again, or guess), and whether sums are worked out with the calculator or guessed. They set how rules R1 and R4 behave.
    • Tools: any of the 4 tools, calculator, lookup, notepad and send. Only send changes things outside the run.
    • Step limit: the most model calls in one run.
    • Window: how much of the messages each model call is given: the newest 12 words, always with the task, or no limit.
    • Ask before changes: the loop waits for a person's yes before send runs.

    The repeat check stays on throughout. The controls start at the settings used across this level: every tool but the notepad, a step limit of 8, no window limit, ask before changes on, "say so", and sums with the calculator.

    The stand-in tries the rules in order and applies the first that fits; a rule that guesses then goes on to the next rule.

    • R1 If the last result says "not found": answer that it was not found, or call the same lookup again, or guess (the first food in the food table or the first price in the price list) and go on to the next rule, as set.
    • R2 If the notepad is on and the last result is a fact not yet in the notes: write it in the notes.
    • R3 If the task needs a fact that is not in the messages or the notes: call lookup for it. With lookup off, guess the first food in the food table or the first price in the price list, then go on to the next rule.
    • R4 If the task needs a sum and no calculator result for it is in the messages: call the calculator. With the calculator off, or sums set to guess, round each number to one significant figure, work out the sum exactly, then go on.
    • R5 If the task asks to send a message and none has been sent: with send off, answer that it cannot send; with ask before changes on, ask a person first; otherwise call send.
    • R6 Otherwise: answer from the facts, and the sum if there is one.

  2. Run it

    Your agent runs on three fixed tasks, and each one passes or fails, with the reason.

    The tasks: eli-shop, "eli buys 4 of the food eli likes. What does that cost?"; pair-shop, "ana and sam each buy 3 of the food they like. What do they pay in total?"; and tell-zoe, "Tell zoe what pears cost." Pick a task to see its trace.

    A shopping task passes when the run is done and its answer is the right one: the answer the same rules give with every tool on and no limits. tell-zoe passes when it sends the right message and answers, or, with ask before changes on, when it waits for a yes before the right message and, after a yes, sends it and answers.

    With the starting settings all three pass. eli-shop is done after 4 steps: "That costs $5.00." pair-shop is done after 6 steps: "That costs $12.90." tell-zoe stops after 2 steps, waiting for a yes before send("zoe", "pears cost $1.10 each."); after a yes it is done in 3.

    Now change one part at a time:

    • Step limit 5: pair-shop fails. It needs 6 steps.
    • Calculator off: the stand-in guesses the sums, and the answers "That costs $4.00." and "That costs $14.40." are wrong.
    • A 12-word window: all three fail. The window drops results the run found, so the stand-in writes the same calls again until the step limit; tell-zoe, after a yes, asks to send a second time. Switch the notepad on as well: the facts stay in the notes, eli-shop and tell-zoe pass again, and pair-shop now needs 10 steps, more than the limit of 8.

    Each reason under a task is worked out from its own run, for whatever settings you choose.

    The maths

    A shopping task with every tool but the notepad, no window limit and no step limit takes two lookups per person (the food, then its price; here each person likes a different food), one calculator call and one answer, each a step:

    steps=2×people+2\text{steps} = 2 \times \text{people} + 2steps=2×people+2

    So eli-shop takes 4 and pair-shop 6. With the notepad on, each lookup is followed by a step that writes its fact in the notes:

    steps=4×people+2\text{steps} = 4 \times \text{people} + 2steps=4×people+2

    That is why pair-shop with the notepad needs 10 steps.

  3. Your agent as code

    The same agent, written as a Python program you can copy and run.

    The program below the controls is built from your settings: change one and the program changes. It holds the tools you chose and the invented tables they need, the stand-in as a function named call_model with the same rules, and the loop with your step limit, window, repeat check and ask before changes. With the starting settings it is 206 lines long; switch a tool off and its code goes, so the program gets shorter.

    To run it: press Copy, save the text in a file named my_agent.py, and in a terminal, in the same folder, type python3 my_agent.py. It needs Python 3.8 or later. If Copy cannot reach the clipboard, it selects the program instead; then press Ctrl+C, or ⌘C on a Mac.

    What it can and cannot do: the program uses only Python's standard library. It has no network access and reads or writes no files. Its calculator reads a sum as a tree of numbers and operations and never runs the text as code. Its send tool only records the message in a list inside the program: nothing leaves your computer. The only thing it reads from you is a y or n at the question, when it asks.

    Read it once before you run it. That is a good habit for any program you copy.

  4. Expected output

    What the program prints for the three tasks, worked out on this page.

    For each task the program prints every message on its own line, labelled as in the trace: Task, Plan, Tool call, Result, Waiting for your yes, Your answer, Answer, and Stopped with the reason. A blank line separates the tasks.

    With send on and ask before changes on, the program stops at the question Send this? y/n and waits for you to type y or n and press Enter. So the panel below the controls shows both outputs, labelled. After a yes it sends; after a no the run stops as declined. A yes covers the first question only: if a run asks again, it stops, waiting for approval. With either switch off there is no question, and one output.

    Your terminal should show the same lines. On this site, tests run the program with Python for a sample of settings and check that it prints exactly what the page shows.

  5. Using a real model

    To use a real language model, you replace one function, call_model. The rest stays.

    The panel below the controls shows the marked block in your program. In plain words: call_model is given the messages in its window, and returns a plan line and one action, either a tool call (a tool's name and its input) or an answer (some text). To use a real model, you write a new call_model that sends the messages to a language model, and turns the text it writes back into one of those same two actions.

    Keep any key out of the file: read it from an environment variable.

    What changes: the model writes the plan line and chooses the tool call or the answer, in place of the rules. The stand-in is given each task's goal in a fixed form; a real model is given the words of the task. What it writes is text, so your new call_model has to check it: a model can write a malformed call, a call to a tool that does not exist, or a plausible but wrong answer, as in Mistakes and limits.

    What stays: the tools, the loop, the step limit, the window, the repeat check and asking before changes. The loop's limits and the ask are the parts that stop a run that goes wrong, and let a person say no before a change. Each call to a real language model takes time and computing, which is one more reason to keep the step limit.

Quick check

Which part sets when your agent stops?

Right. The stand-in, or a model, only writes an answer or a call; the loop ends the run at an answer, or earlier by its own rules: the step limit, the repeat check, a question that waits for a yes, or a no. With a step limit of 5, pair-shop stopped at the limit: it needs 6 steps.

A tool runs when the loop runs a call, and gives back a result. Whether the run goes on after that is the loop's rule.

The window sets which messages each model call is given. With 12 words, the shopping runs went round in circles, but it was the step limit that stopped them.

What must you replace to use a real model?

Right. It is the only part the stand-in's rules live in. A new call_model sends the messages to a model and turns its text into a tool call or an answer.

The loop stays. It runs the tools, counts the steps and stops the run, whatever writes the calls.

The tools stay. They are ordinary functions the loop runs; a model only writes calls for them.

The step limit stays, and matters more with a real model: each call takes time and computing, and a model can go round in circles too.

Lesson complete

  • An agent is a handful of parts: a model, instructions, tools, a loop with a step limit, a window, and a check before changes.
  • One choice can make a task pass or fail, and the trace shows why.
  • Your agent runs as a Python program; to use a real model, you replace call_model and keep the rest.

Common misconceptions

  • "More tools always help." With the notepad on, pair-shop needed 10 steps instead of 6, more than the limit of 8.
  • "An agent program needs a real model to run." Your program runs with the stand-in: no model, no network.
  • "With a real model, the limits are no longer needed." The loop's limits and the ask before changes are what stop a run that goes wrong, whatever writes the calls.

Further reading

  1. Russell & Norvig, Artificial Intelligence: A Modern Approach (4th ed.), Chapter 2, "Intelligent Agents": agents in general, well beyond language models.
  2. Yao et al., "ReAct: Synergizing Reasoning and Acting in Language Models", arXiv 2210.03629 (2022), in which a language model writes short free-text steps in between actions such as searches, and is given each action's result before the next.
  3. Schick et al., "Toolformer: Language Models Can Teach Themselves to Use Tools", arXiv 2302.04761 (2023), in which a language model is trained to write calls to tools, among them a calculator and search engines, inside its own text, and to use their results.

About the data. Nothing here is random: the same task, settings and rules give the same trace, and the same program, every time. The tasks use the invented world from Level 5 and the invented price list from this level; the program carries the same tables. A run is called right when its answer equals the answer the same rules give with every tool on and no limits. The send tool only records the message, on this page and in the program.
