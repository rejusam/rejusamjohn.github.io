ML Explorer · Level 6 · Agents

Build your own agent

An agent is a handful of parts you can name and choose. Choose them, run your agent on three tasks, and take it home as a small Python program.

About 12 minutes · Every run, every pass or fail and the program itself are computed in your browser

Overview

The last five lessons took an agent apart: the loop in What is an agent?, tools in Tools, the step limit and the repeat check in The loop and when to stop, the window in Memory, and asking before changes in Mistakes and limits. Here you put the parts together.

Your agent runs on three fixed tasks, and the page says whether each one passes, and why. Then the same agent appears as a Python program that you can copy, read and run on your own computer, with no model and no network.

You'll learn

  • to name the parts of an agent and choose each one
  • how one choice can make a task pass or fail
  • how your agent looks as a program, and which part a real model replaces

  1. The parts of your agent

    The last five lessons taught these parts. Choose them here.

    Look at the picture: one box per part.

    • Model: a stand-in with 6 fixed rules. A real agent uses a language model, which can write a wrong call.
    • Instructions: what to do if lookup finds nothing; how to do sums.
    • Tools: any of the 4. Only send changes things outside the run.
    • Step limit: the most model calls in a run. The loop also stops at an answer, a repeat call, a wait for a yes or a no.
    • Window: how many recent words each call is given, plus the task.
    • Ask before changes: a yes before send runs.
    The stand-in's rules in full

    On each step the stand-in tries these in order and applies the first that fits. A rule that guesses then goes on to the next rule. The "Why this step" box in the trace names them R1 to R6.

    • R1 If the last result says "not found": answer that it was not found, or call the same lookup again, or guess (the first food in the food table or the first price in the price list) and go on to the next rule, as set.
    • R2 If the notepad is on and the last result is a fact not yet in the notes: write it in the notes.
    • R3 If the task needs a fact that is not in the messages or the notes: call lookup for it. With lookup off, guess the first food in the food table or the first price in the price list, then go on to the next rule.
    • R4 If the task needs a sum and no calculator result for it is in the messages: call the calculator. With the calculator off, or sums set to guess, round each number to one significant figure, work out the sum exactly, then go on.
    • R5 If the task asks to send a message and none has been sent: with send off, answer that it cannot send; with ask before changes on, ask a person first; otherwise call send.
    • R6 Otherwise: answer from the facts, and the sum if there is one.

    The "when lookup finds nothing" menu sets R1, and the sums menu sets R4. The repeat check (the same call twice in a row stops the run) is always on. The controls start at the settings used across this level: every tool but the notepad, a step limit of 8, no window limit, ask before changes on, "say so", and sums with the calculator.

  2. Run three tasks

    Now run your agent on three tasks.

    Tasks: eli-shop (one person's shopping), pair-shop (two people's) and tell-zoe (tell zoe a price). Pick one. All pass at the start. Now change one part at a time:

    • Step limit 5: pair-shop stops with no answer; it needs 6 steps.
    • Calculator off: the sums are guessed, so both shopping answers are wrong.
    • 12-word window: facts drop out and calls repeat: shopping runs hit the step limit, tell-zoe asks twice.
    • Notepad too: facts are kept, but pair-shop needs 10 steps, more than 8.

    Note: every lookup here finds its fact, so the "when lookup finds nothing" menu changes only the program.

    The maths

    The tasks: eli-shop, "eli buys 4 of the food eli likes. What does that cost?"; pair-shop, "ana and sam each buy 3 of the food they like. What do they pay in total?"; and tell-zoe, "Tell zoe what pears cost."

    A shopping task passes when the run is done with the right answer: the one the same rules give with every tool on and no limits. tell-zoe passes when it sends the right message and answers, or, with ask before changes on, when it waits for a yes before the right message and, after a yes, sends it and answers.

    With the starting settings, pair-shop answers "That costs $12.90." and eli-shop is done after 4 steps: "That costs $5.00." tell-zoe stops after 2 steps, waiting for a yes before send("zoe", "pears cost $1.10 each."); after a yes it is done in 3.

    With the calculator off, the stand-in rounds each number to one significant figure: "That costs $4.00." and "That costs $14.40." With a 12-word window, tell-zoe asks to send a second time after a yes; with the notepad on as well, eli-shop and tell-zoe pass again.

    A shopping task with every tool but the notepad, no window limit and no step limit takes two lookups per person (the food, then its price; here each person likes a different food), one calculator call and one answer, each a step:

    steps=2×people+2\text{steps} = 2 \times \text{people} + 2steps=2×people+2

    So eli-shop takes 4 and pair-shop 6. With the notepad on, each lookup is followed by a step that writes its fact in the notes:

    steps=4×people+2\text{steps} = 4 \times \text{people} + 2steps=4×people+2

    That is why pair-shop with the notepad needs 10 steps, more than the limit of 8.

  3. Your agent as a program

    Next, the same agent as a Python program.

    Look at the program under the controls. It is built from your settings: switch a tool off and its code goes. With the starting settings it is 206 lines.

    The stand-in's rules sit in a function named call_model. The loop around it has your step limit, window, repeat check and ask before changes.

    To run it, press "Copy" and save the text as my_agent.py. In a terminal in that folder, type python3 my_agent.py. It needs Python 3.8 or later.

    It runs with the stand-in: no model and no network. Read it once before you run it.

    What the program can and cannot do

    The program uses only Python's standard library. It has no network access and reads or writes no files. Its calculator reads a sum as a tree of numbers and operations and never runs the text as code. Its send tool only records the message in a list inside the program: nothing leaves your computer. The only thing it reads from you is a y or n at the question, when it asks.

    If "Copy" cannot reach the clipboard, it selects the program instead; then press Ctrl+C, or ⌘C on a Mac. Reading a program before you run it is a good habit for any program you copy.

  4. What the program prints

    Then run it. Here is what it should print.

    Look at the panel: the program runs the three tasks in turn, one line per message, labelled as in the trace: Task, Plan, Tool call, Result, Waiting for your yes, Your answer, Answer, and Stopped with the reason. Your terminal should show the same.

    With send and ask before changes both on, the program stops at the question Send this? y/n and waits. The panel shows two outputs: one if you type y (it sends), one if you type n (the run stops as declined).

    Note: with either switch off there is no question, and one output. A yes covers the first question only; a run that asks again stops there.

    How this is checked

    The panel is worked out on this page from the same runs as the traces. On this site, tests run the program with Python for a sample of settings and check that it prints exactly what the page shows. A blank line separates the tasks.

  5. Swapping in a real model

    Last, the one part a real model would replace: call_model.

    Look at the marked block. call_model is given the messages in its window and returns a plan line and one action: a tool call or an answer.

    To use a real model, write a new call_model that sends the messages to a language model and turns its text into one of those actions. Keep any key out of the file: read it from an environment variable.

    Everything else stays: the limits still stop a run that goes round in circles, and the ask lets a person say no.

    Note: a real model can call a tool that does not exist, or write a wrong answer.

    What changes with a real model

    The model writes the plan line and chooses the tool call or the answer, in place of the rules. The stand-in is given each task's goal in a fixed form; a real model is given the words of the task. What it writes is text, so your new call_model has to check it: a call can be cut short, name a tool that does not exist, or be fine while the answer is wrong, as in Mistakes and limits.

    Each call to a real language model takes time and computing, which is one more reason to keep the step limit.

Quick check

Which part sets when your agent stops?

Right. The stand-in, or a model, only writes an answer or a call; the loop ends the run at an answer, or earlier by its own rules: the step limit, the repeat check, a question that waits for a yes, or a no. With a step limit of 5, pair-shop stopped at the limit: it needs 6 steps.

A tool runs when the loop runs a call, and gives back a result. Whether the run goes on after that is the loop's rule.

The window sets which messages each model call is given. With 12 words, the shopping runs went round in circles, but it was the step limit that stopped them.

What must you replace to use a real model?

Right. It is the only part the stand-in's rules live in. A new call_model sends the messages to a model and turns its text into a tool call or an answer.

The loop stays. It runs the tools, counts the steps and stops the run, whatever writes the calls.

The tools stay. They are ordinary functions the loop runs; a model only writes calls for them.

The step limit stays, and matters more with a real model: each call takes time and computing, and a model can go round in circles too.

Lesson complete

  • An agent is a handful of parts: a model, instructions, tools, a loop with a step limit, a window, and a check before changes.
  • One choice can make a task pass or fail, and the trace shows why.
  • Your agent runs as a Python program; to use a real model, you replace call_model and keep the rest.

Common misconceptions

  • "More tools always help." With the notepad on, pair-shop needed 10 steps instead of 6, more than the limit of 8.
  • "An agent program needs a real model to run." Your program runs with the stand-in: no model, no network.
  • "With a real model, the limits are no longer needed." The loop's limits and the ask before changes are what stop a run that goes wrong, whatever writes the calls.

Further reading

  1. Russell & Norvig, Artificial Intelligence: A Modern Approach (4th ed.), Chapter 2, "Intelligent Agents": agents in general, well beyond language models.
  2. Yao et al., "ReAct: Synergizing Reasoning and Acting in Language Models", arXiv 2210.03629 (2022), in which a language model writes short free-text steps in between actions such as searches, and is given each action's result before the next.
  3. Schick et al., "Toolformer: Language Models Can Teach Themselves to Use Tools", arXiv 2302.04761 (2023), in which a language model is trained to write calls to tools, among them a calculator and search engines, inside its own text, and to use their results.

About the data. Nothing here is random: the same task, settings and rules give the same trace, and the same program, every time. The tasks use the invented world from Level 5 and the invented price list from this level; the program carries the same tables. A run is called right when its answer equals the answer the same rules give with every tool on and no limits. The send tool only records the message, on this page and in the program.
